# 关系型 AI 记忆偏移实验｜第一步产出：可行性分析

> 本文是对《关系型 AI 记忆偏移实验｜DSH 开发任务书 V0.2》第二十三节所列 1–10 项的逐条回答。
> 按任务书要求：**这一步不写完整项目代码**，只做需求分析、复用调研、方案与成本判断。
> 产出全部集中在 `memory-drift-experiment/` 一个目录里，迁移后可直接整体删除。

---

## 0. 一句话结论

用 **纯 Python + OpenAI 兼容 API + 本地 JSON/SQLite 文件**，复刻成熟项目的数据结构（Mem0 的记忆条目模型、Character Card V2 的人格字段），
只自研 **记忆版本保存 + 记忆变化记录 + 实验对比** 这三件任务书点名的能力。
预计开发期 API 成本 **≈1 元**，一次完整实验 **≈1–3 元**，**100–130 元预算完全够用，而且有大量冗余**。

## 1. 需求分析

### 1.1 实验真正要回答的问题

> 一个拥有初始人格的 LLM，在持续对话和记忆整理之后，它对过去经历的记忆究竟会发生什么变化？

可被验证的最小闭环（任务书第四节）：

```
初始人格 → LLM → 正常聊天 → 产生真实事件 → 保存原始事件
        → 生成长期记忆 → Memory V1 → 继续聊天 → 重新整理记忆 → Memory V2 → V3
        → 询问过去事件 → 记录 AI 当前回忆 → 对比：原始事实 / V1 / V2 / V3 / 最终回忆
```

### 1.2 拆成需求项与优先级

| # | 需求 | 来源 | 优先级 | 判定标准（可验收） |
|---|------|------|--------|-------------------|
| R1 | 能聊天，且人格稳定生效 | 八、十八 | 必须 | 同一人格文件下，多轮回复风格一致；人格文件在实验中被禁止修改 |
| R2 | 原始事件**不可覆盖** | 五 | 必须 | `raw/` 下事件一旦写入，无任何代码路径可修改；文件哈希可校验 |
| R3 | 长期记忆生成（从对话提取） | 六 | 必须 | 每次整理产出一个新的 `memory_vN.json`，不覆盖上一版 |
| R4 | 记忆版本化 | 六 | 必须 | 目录中同时存在 v1/v2/v3 完整快照，可独立打开对比 |
| R5 | Changelog（新增/删除/修改/表达变化） | 六 | 必须 | 每个版本间有一份机器可比对的差异记录 |
| R6 | 事实 / 推断 / 未知 三分标记 | 六 | 可选（降级项） | 记忆条目带 `type: FACT / INFERENCE / UNKNOWN` 字段 |
| R7 | 记忆检索 | 六、八 | 必须 | 每轮对话记录「本轮检索到了哪些记忆条目」 |
| R8 | 回忆探针 + 记录最终回忆 | 九 | 必须 | 阶段 4 的提问原话与模型回答**原样**落盘 |
| R9 | 对比分析 | 九 | 必须 | 逐条关键事实生成 原始事实 vs V1 vs V2 vs V3 vs 最终回忆 的对照表 |
| R10 | 成本可计量 | 十七 | 必须 | 每次调用记录 model / 输入 token / 输出 token / 缓存命中 / 估算费用 |
| R11 | 可迁移 | 十一～十六 | 硬性 | 整个项目目录可直接复制；无绝对路径；Key 在 `.env`；有 README |
| R12 | 不过度开发 | 十九、二十 | 硬性 | 不含多 Agent、语音、3D、向量库集群、训练、MCP、Docker 集群等 |

### 1.3 明确不做的（任务书二十节）

多 Agent / 复杂关系系统 / 自主行动 / 主动联系 / 复杂情绪模型 / 人格自主进化 / 语音 / 3D / Avatar /
手机 App / 云服务器 / 数据库集群 / 向量数据库 / 模型训练 / LoRA / RAG 大型架构 / 世界模拟 / MCP / Kubernetes / Docker 集群。

**判定规则（任务书十九节）**：任何新功能先问「是否直接服务于记忆偏移实验」，不是就默认暂缓。

## 2. 可复用的成熟开源项目调研

调研口径：**能在自己电脑上跑、不产生长期费用、依赖简单、方便整体迁移**。这一点比「功能强」更重要。

### 2.1 Memory / 长期记忆

| 项目 | 能力 | 对本项目的实际问题 | 复用结论 |
|------|------|-------------------|---------|
| [mem0](https://github.com/mem0ai/mem0) | 记忆提取 / 更新 / 检索，自带 ADD–UPDATE–DELETE 变更语义 | 默认要配向量库与 embedding（[OSS 配置文档](https://docs.mem0.ai/open-source/configuration)），想零依赖就得挂本地 embedding；它内部还会**自动改写旧记忆** | **借用数据模型与变更语义，不引入框架** |
| [Letta（原 MemGPT）](https://github.com/Dawson-Ren/MemGPT) | 自编辑记忆、分层记忆、SQLite 落库 | 是完整的 stateful agent server，带自己的运行时与迁移体系；学习/迁移成本明显高于本次实验需要 | 不引入 |
| Zep | 时序知识图谱记忆 | 面向服务化部署，组件重 | 不引入 |
| Cognee | 知识图谱式记忆 | 依赖图数据库/向量栈 | 不引入 |
| 各类「单文件记忆层」小项目 | remember/recall/forget API | 实现思路可参考，但都缺少**版本快照 + 变更记录** | 参考思路 |

> 关键判断：mem0 这类框架的核心行为是**就地更新记忆**（旧记忆被改写或删除）。
> 而这恰好是任务书第五节**明令禁止**的：「原始事件不能被覆盖」。
> 所以框架本身与实验目的存在结构性冲突 —— 我们**只借它的结构，不借它的运行时**。

### 2.2 人格 / Character

| 项目 | 说明 | 复用结论 |
|------|------|---------|
| Character Card V2（[格式说明](https://github.com/bradennapier/character-cards-v2)） | 事实标准的人格字段集：name / description / personality / scenario / first_mes / mes_example / system_prompt / post_history_instructions | **直接采用其字段命名**，落成 `personality.json` |
| SillyTavern 生态 | 成熟的角色卡与 prompt 拼装 | 只借字段与拼装顺序，不装客户端 |
| [UPEX 人格交换格式](https://github.com/LeNotFound/UPEX) | 跨平台人格交换标准 | 可选参考 |

结论：人格部分**不需要写引擎**。一个 `personality.json` + 一段稳定的 system prompt 拼装函数即可，符合任务书「一个稳定的初始人格作为实验起点」。

### 2.3 对话 / LLM 调用 / 持久化 / 日志

| 需求 | 复用对象 | 结论 |
|------|---------|------|
| LLM API 调用 | OpenAI 兼容接口 + 官方 `openai` SDK（也可只用 `requests`） | 直接借用 |
| Conversation History | Python 标准库 `json` / `jsonlines` 追加写 | 直接借用标准库，不必引框架 |
| 数据持久化 | SQLite（标准库 `sqlite3`）存对话与调用日志；JSON 文件存记忆版本 | 直接借用标准库 |
| 日志 | 标准库 `logging` | 直接借用 |
| 记忆检索 | 关键词/标签匹配（标准库即可） | 自研极简版；**不引入向量数据库** |
| Token / 成本统计 | API 返回的 `usage` 字段（含缓存命中） | 直接借用 |

### 2.4 结论：借用 / 连接 / 自研三分表（任务书第二十三节第 3 项）

| 分类 | 内容 |
|------|------|
| **可以直接借用** | LLM API 调用（openai SDK）· HTTP/JSON/日志/SQLite（标准库）· 人格字段规范（Character Card V2）· 记忆条目结构（Mem0 风格）· `.env` 配置约定 |
| **需要简单连接** | 人格 → system prompt 拼装 · 检索到的记忆 → 对话上下文 · API `usage` → 成本账本 · 记忆版本 → Changelog 生成 |
| **必须自己开发**（任务书点名） | **记忆版本保存**（快照、永不覆盖）· **记忆变化记录**（版本间 diff）· **记忆偏移实验对比**（原始事实 vs V1/V2/V3 vs 最终回忆）· **回忆探针记录** |

## 3. 最低成本技术方案

### 3.1 技术栈

- 语言：**Python 3.11+**（标准库够用）
- 依赖：**只有 `openai` 与 `python-dotenv`**（`requirements.txt` 两行）；聊天与整理也可用本地 Ollama（OpenAI 兼容，零成本）
- 存储：SQLite（对话、调用账本）+ UTF-8 JSON（人格、原始事件、记忆版本、变更记录）
- 交互：命令行 REPL；不需要 Web
- 迁移：整个目录复制即走

### 3.2 数据模型（自研部分的核心）

```
raw/event_<id>.json          一次原始事件：用户原话，只写不改（含 sha256）
memory/v001.json             记忆快照：条目数组 + 生成元信息
memory/v002.json
memory/changelog/v001__v002.json   版本差异：added / removed / modified / reworded
recall/<probe_id>.json       回忆探针：提问原话 + 模型回答原文 + 当轮注入的记忆版本
```

记忆条目（借 Mem0 结构 + 任务书要求的三分标记）：

```json
{
  "id": "mem_0007",
  "type": "FACT",
  "text": "用户曾在夜间时段工作约一年多。",
  "source_event_ids": ["raw_event_001"],
  "confidence": 0.9,
  "first_seen_version": "v001",
  "last_modified_version": "v002"
}
```

记忆版本文件：

```json
{
  "version": "v002",
  "created_at": "…",
  "model": "deepseek-flash",
  "source_range": {"conversation_from": "…", "conversation_to": "…"},
  "previous_version": "v001",
  "items": [ … ]
}
```

### 3.3 记忆检索策略（刻意保持简单）

关键词 + 标签匹配，取 top-k 注入上下文，**不引入 embedding 与向量库**。
原因有两条：一是任务书二十节明确禁止向量数据库；二是**embedding 会引入一个和被测对象无关的语义相似度变量**，让「AI 记不清」和「检索没召回」混在一起，无法归因。

### 3.4 成本控制落地（任务书十七节）

- 短 system prompt，只注入本轮检索到的记忆条目（不整包丢历史）
- 每轮只带最近 N 对对话（N 可配，默认 6）
- 整理记忆单独调用，且只在阶段节点触发，不做每轮整理
- 每次调用把 `usage` 写入账本：`model / prompt_tokens / completion_tokens / cache_hit_tokens / cached / 估算费用`
- 提供一条命令输出：总调用次数 / 总 token / 总花费

## 5. 开发顺序（任务书第十八节）

| 阶段 | 内容 | 完成判据 | 预估成本 |
|------|------|---------|---------|
| Phase 1 | 用户 → LLM → 回复 | 命令行能连续对话 | < 0.05 元 |
| Phase 2 | 加入初始人格 | 人格文件生效且稳定 | < 0.05 元 |
| Phase 3 | 保存原始对话（含原始事件） | 每次对话原样落盘，`raw/` 有事件文件 | 0 |
| Phase 4 | 加入 Memory（复用优先 → 极简自研） | 能从对话产出 `memory_v1` | ≈0.1 元 |
| Phase 5 | 加入 Memory Version | v1/v2/v3 同时存在、互不覆盖 | ≈0.1 元 |
| Phase 6 | 加入 Changelog | 每两版之间有 diff 记录 | ≈0.1 元 |
| Phase 7 | 实际记忆偏移实验 | 完成 3 轮整理 + 回忆探针 | ≈1–3 元 |
| Phase 8 | 对比实验结果 | 产出对比报告，可判定 A–H 中的哪种结果 | ≈0.1 元 |

开发期总消耗预计 **< 1 元**（若 Phase 1–2 用本地 Ollama 则接近 0）。

## 6. 成本估算（任务书第十七、二十三节）

### 6.1 当前可用价格口径

DeepSeek 官方计价页（[模型 & 价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，单位：元 / 百万 tokens）：

| 模型 | 输入（缓存命中） | 输入（缓存未命中） | 输出 |
|------|----------------|------------------|------|
| `deepseek-flash` | 0.02（空闲）/ 0.04（高峰） | 1（空闲）/ 2（高峰） | 4（空闲）/ 8（高峰） |
| `deepseek-v4-pro` | 0.15（空闲）/ 0.30（高峰） | 4.5（空闲）/ 9（高峰） | 13.5（空闲）/ 27（高峰） |

- 高峰时段：周一至周五 9:00–12:00、14:00–18:00；其余时段及节假日全天为**空闲（半价）**。
- 缓存命中价极低，意味着**固定不变的人格 prompt 与任务书式指令几乎免费**。

### 6.2 一次完整实验的用量模型（按高峰价保守估）

假设：对话 40 轮 + 记忆整理 3 次 + 回忆探针 3 次 = **46 次调用**。

| 调用类型 | 次数 | 每次输入 | 每次输出 | 输入小计 | 输出小计 |
|---------|------|---------|---------|---------|---------|
| 普通对话 | 40 | 约 1.5k tokens（含记忆注入） | 约 0.5k | 60k | 20k |
| 记忆整理 | 3 | 约 12k tokens（整段对话摘要） | 约 1.5k | 36k | 4.5k |
| 回忆探针 | 3 | 约 2k tokens | 约 0.5k | 6k | 1.5k |
| **合计** | **46** | | | **≈102k** | **≈26k** |

按 **高峰** 单价（未命中 2 元/百万输入、8 元/百万输出）：

```
输入：0.102 × 2  ≈ 0.20 元
输出：0.026 × 8  ≈ 0.21 元
一次完整实验 ≈ 0.41 元
```

按 **空闲** 单价约为 **0.21 元**。加上开发期调试与返工，**整个项目落到 1–5 元量级**。
即便把记忆整理换成 `deepseek-v4-pro`、或把对话量放大 20 倍，也仍在 **20–40 元**以内。

### 6.3 对 100–130 元预算的判断

**完全够，而且余量很大。** 三条建议：

1. 预算是**上限不是目标**，不要为了「花掉」而扩大规模；花不完是好事。
2. 「DSH 与 Codex 二选一」这条约束与本实验不冲突：**任务书本身就是用 DSH 写的**，开发环境已经确定，无需再购买第二个付费工具。
3. 预留 20–30 元作为**重复实验的预算**（这是真正值钱的部分：同一实验跑 3 次看漂移是否稳定复现，比一次跑很长更有研究价值）。

## 7. 最大的技术风险（任务书第二十三节第 9 项）

按「会不会毁掉实验结论」排序：

| 级别 | 风险 | 为什么致命 | 对策 |
|------|------|-----------|------|
| **P0** | **检索失败被误读成记忆漂移** | 记忆 V3 里明明还留着那条事实，只是这一轮没被检索进上下文，AI 答不出来 —— 结论会被写成「记忆丢失」，而实际是工程问题 | 每轮落盘「本轮检索命中的条目」；探针分两种：**不注入记忆** 与 **注入最新版记忆**，分别记录 |
| **P0** | **整理提示词自带压缩倾向** | 如果 `consolidate` 的 prompt 说「简洁地总结」，V2 的信息丢失就是**你写死的**，不是模型自然漂移 | 提示词外置可版本化；整理指令写成中性（保真优先、禁止合并不同事实）；保留 V1 作为较完整基线 |
| **P0** | **模型/版本中途变化** | 换模型等于换了被测对象，前后不可比 | 每个版本与每次调用都记录 `model` 与时间戳；实验期间锁定模型 |
| P1 | 对话历史被当成长期记忆 | 原始对话一注入，模型是「看着原文回答」，测的就不是记忆 | 阶段 4 探针时**不注入原始对话**，只注入目标记忆版本；两者在数据层严格分开 |
| P1 | 探针提问有引导性 | 任务书九节的原话是「你还记得我之前说过的那件事吗？」——**没点名是哪件事**，这是对的，不要改成「你还记得夜班的事吗」 | 探针问题提前固定并写入 `experiments/`，全程不改 |
| P1 | 事实与推断混合 | 任务书十节 D/F 类结果，需要能定位到是哪一步引入的 | 条目强制带 `type`，Changelog 记录类型变化（FACT→INFERENCE 要显式记下来） |
| P2 | 迁移丢失或路径写死 | 借来的电脑要还，实验数据带不走就全废 | 相对路径 + `.env` + 单目录自包含；每个阶段结束打一次 zip 备份 |
| P2 | 成本不可见 | 无法回答「花了多少钱」 | 账本从 Phase 1 就开始记，不留到最后补 |

## 8. 可迁移性自检（任务书第十一～十六节）

| 要求 | 方案是否满足 |
|------|-------------|
| 不依赖 `C:\Users\某人\Desktop\xxx` 绝对路径 | 满足：全部相对路径，配置项集中在 `config/settings.json` |
