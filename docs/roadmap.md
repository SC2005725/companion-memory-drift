## 五、已排除的方向（**不再重复讨论**）

> 这些方向**已经过证据调查并正式收口**。价值是**排除无效开发**，不是待办。

| 事项 | 决策 | 依据 |
|---|---|---|
| **缓存友好注入** | 🚫 **暂缓** | 实测 chat 缓存命中率 **48.9%**，**推翻了"动态段使缓存全废"的假设**；且缺分段 token 计量，收益无法可靠估算 |
| **分段注入日志** | 🚫 **暂不增加** | 无近期优化计划时，观测代码只扩大维护面 |
| `memory.retrieve_scored` | 🚫 **不修复** | **有意预留的诊断接口**（生产用 `retrieve`） |
| `user_model.adjudicate_by_observation` | 🚫 **不修复** | **有意预留**，等主题键接口；接入只会得到永不触发的调用点，**比没接更危险** |
| 引入向量库 / embedding | 🚫 **不做** | 会让漂移**不可归因** —— 这是项目的核心取舍 |

## 七、长期主线

**当前主线不是"再做功能"，是"通过真实连续互动验证系统是否协同变化"。**

```
用户互动
  → 经历与事件记录
  → 记忆与相关状态更新
  → 关系 / 用户模型 / 自我模型 / 情绪变化
  → 人格与行为决策
  → 影响后续回复
  → 新的互动结果再次进入系统
```

**不要求每条消息都触发全部模块。** 要判断的是：
**不同事件在什么条件下触发哪些模块，以及这些触发关系是否合理。**

> **若长期跑下来情绪与发展闭环仍是空的 —— 那不是"还没到"，是链路有问题，那时回来查。**

## 八、已知限制（如实列出）

| 限制 | 说明 |
|---|---|
| **无长期真实运行验证** | 最大的一条 |
| **关键词检索召不回同义改写** | 这是"拒绝 embedding"的**代价**，不是 bug |
| **做不到无人值守运行** | 无调度器、无常驻进程、**无法真推送** |
| **`verify` 检测的是意外改动，不是有意伪造** | 原始事件表没有哈希链 |
| **归档层在真实数据里长期为 0 条** | 机制正确，但缺可归档的候选 |
| **提示词注入面未做系统测试** | 一次对抗测试通过，不构成结论 |
| **`run_python` 不是沙箱** | 它是本机任意代码执行，只是默认不注册 + 有超时与账本 |
