# 系统架构

> 本页说明**程序实际怎么工作** —— 模块职责、调用关系、数据流与关键约束。
> 面向开发者与后续接手的人。
>
> **最后核对：2026-10-25** ｜ 依据：源码直读 + 生产数据计数 + 离线自测

---

## 一、一句话

共生把「记忆 / 关系 / 人格 / 用户模型 / 自我模型 / 情绪」拆成**六个职责分离的模块**，
每一轮对话按固定顺序读取它们、组装上下文、调用一次模型、再把结果落盘。

**核心取舍：确定性优先于聪明。**
分类、关系推导、用户建模、行为审计**全部是规则**，不是模型判断 ——
因为这套东西的价值在于能回答「**为什么这条被这样处理**」。

## 二、模块边界

| 模块 | 文件 | 职责 | 不该做的事 |
|---|---|---|---|
| **人格** | `src/persona.py` | 稳定底色（sha256 守护）· 初始角色模型 · 表达调整 · 立场表达 · 发展闭环闸门 | 不改稳定层 |
| **记忆** | `src/memory.py` | 条目 / 分类分层 / 检索 / 衰减 / 来源 / 隐私 / 关注点 | 不覆盖历史版本 |
| **整理** | `src/consolidate.py` | 把对话批量整理成记忆版本（**唯一的记忆写入者**） | 不逐轮调用 |
| **关系** | `src/relationship.py` | 由**事件流确定性推导**状态（纯函数、可重放） | 不用计数器 |
| **用户模型** | `src/user_model.py` | 「她眼中的你」—— 判断的形成 / 修正 / 保留不确定性 | 不覆盖被修正的判断 |
| **自我模型** | `src/self_model.py` | 「她自己的做法」—— 只开放到**做法**层 | 不改价值观/边界 |
| **情绪** | `src/emotion.py` | 7 词表 · 半衰期衰减 · 6 道证据闸门 | 不宣称主观感受 |
| **心跳** | `src/heartbeat.py` | 主动性检查（**7 条确定性决策规则**） | 不改规则；无调度器 |

### 支撑层

| 层 | 文件 | 说明 |
|---|---|---|
| **模型调用** | `src/llm.py` | **唯一出口** —— 成本账本、缓存命中、空回复重试都在这 |
| **模型适配** | `src/model_adapter.py` | 统一适配层（本地 / 免费 / 现有客户端） |
| **持久化** | `src/storage.py` | SQLite schema 与全部表操作 |
| **快照语义** | `src/snapshots.py` | 关系 / 自我 / 用户模型共用的版本+侧车逻辑 |
| **路径** | `src/paths.py` | 全部目录常量（`ensure_dirs()` 负责创建） |
| **工具层** | `src/tools/` | 接口 / 权限三档 / 注册表 / 内建工具 |

## 三、一轮对话的调用链

**全部在一个函数里：`src/chat.py` 的 `send_once`（约 400 行）**

```
用户输入
 │
 ├─ persona.assert_persona_unchanged()      人格被改动 → 立刻中止，不静默继续
 │
 ├─ relationship.current_state()            读关系状态（本轮开始时的快照）
 ├─ self_model.learn_from_text()            ★ 写：自我模型
 ├─ self_model.render_for_prompt()          ★ 读：用**刚更新后**的（同轮生效）
 ├─ user_model.detect_signals / merge_claims ★ 写：用户模型
 │
 ├─ memory.retrieve(...) → retrieve.retrieve_and_log(...)
 │     → 写 retrievals（涵义：**这一轮真正摆到她面前的记忆**）
 │     隐私被扣下的条目**不进** hit_item_ids
 │
 ├─ memory.pick_concerns(...)               关注点（需要 ≥2 字 2-gram 重叠）
 ├─ persona.pick_stance(...)                立场表达（两道闸门都过才有值）
 │
 ├─ persona.render_expression_adjustment(关系 / 用户模型 / 记忆命中数 /
 │                                       话题种子 / 关注点 / 立场 / 情绪)
 │
 ├─ build_messages(...)                     组装 9 段 system + 历史 + 本轮用户
 ├─ storage.record_concern_injections(...)  P0 留痕：**查真实 messages 判 injected**
 │
 ├─ call_model(messages, purpose="chat")    ★ 唯一模型调用
 ├─ (可选) run_tool_loop(...)               工具多步（上限 5 次）
 │
 ├─ storage.save_turn(...)                  落对话
 ├─ events.detect → storage.create_event    原始事件
 ├─ relationship.detect → record_relationship_event
 ├─ snapshots.save_snapshot(!)              关系 / 自我 / 用户模型快照
 ├─ heartbeat.maybe_tick(...)               7 条规则决定「动不动」
 └─ maybe_auto_consolidate(...)             每 20 轮触发一次整理
```

### ⚠️ 一个刻意的顺序

`render_expression_adjustment` 用的是**本轮开始时读到的关系状态**，
而本轮新增的关系事件在它**之后**才记录。

**→ 本轮表达不受本轮新事件影响，新状态下一轮才生效。**
这是**正确设计**（不该用刚发生的事件改变同一句话的语气），
但也意味着「状态更新 → 表达影响」**天然滞后一轮**。

## 四、注入顺序（`build_messages`）

```
 0  表达调整      每轮变    ← 关系 / 用户模型 / 命中数 / 话题种子 / 关注点 / 立场 / 情绪
 1  人格          静态      ← personality.json（sha256 守护，程序不可改）
 2  初始角色模型  准静态    ← profile.json
 3  记忆          每轮变    ← 检索结果（预算 700 字符）
 4  关系状态      每轮变
 5  用户模型      每轮变
 6  自我模型      每轮变
 7  待处理意图    常变
 8  工具清单      静态-ish
 9  历史对话
10  本轮用户输入
```

**9 段都是独立的 system 消息** —— 便于事后核对「这一轮到底给模型看了什么」。

> ⚠️ **已知的代价**：第 0、3–7 段每轮都在变，且都排在历史之前 →
> **稳定前缀每轮被打断**。实测 chat 缓存命中率 **48.9%**（339 次）。
> 结构调整**已评估并暂缓**（缺分段 token 计量，收益无法可靠估算）。

## 五、数据流与存储

```
对话 ──save_turn──▶ conversations（320 轮）
  │
  ├─ events.detect ──▶ events（原始事件，带 sha256）
  │
  ├─ 每 20 轮 ──consolidate──▶ memory/versions/vNNN.json + .sha256
  │                            └─ changelog/（版本差异）
  │
  ├─ relationship.detect ──▶ relationship_events（10 次）──派生──▶ 快照
  ├─ user_model ──▶ user_model_events（11 条）──▶ 快照
  ├─ self_model ──▶ 快照
  ├─ emotion ──▶ emotion/state_vNNN.json
  │
  ├─ 每轮检索 ──▶ retrievals（记「真正摆到她面前的记忆」）
  ├─ 关注点注入 ──▶ concern_injections（P0 留痕）
  ├─ 工具调用 ──▶ tool_calls
  ├─ 模型调用 ──▶ api_calls + logs/ledger.jsonl（逐次成本）
  └─ 心跳 ──▶ heartbeat_runs + pending_actions
```

### 不变性约束

| 约束 | 实现 |
|---|---|
| **记忆只追加** | `memory/versions/` 版本号递增；v004 **永不覆盖** |
| **人格稳定层程序不可改** | `assert_persona_unchanged()` —— 越界**直接中止会话** |
| **原始数据无删除/修改命令** | 刻意的；`verify` 命令可复核 |
| **所有模型调用走一个出口** | `llm.call_model` —— 否则账本会漏 |
| **数据库验证必须隔离** | `storage.redirect_db()`；断言临时路径 ≠ 生产库 |

## 七、离线自测

python src/main.py selftest     # 无需 API Key

python src/main.py doctor       # 环境与配置检查

| 跳过项 | 为什么 |
|---|---|
| `selftest_memory` 的真实记忆回归 | 依赖**真实文本分布**，现场夹具覆盖不到那个 bug |

## 九、刻意的"不做"

| 不做 | 原因 |
|---|---|
| **不用向量库 / embedding** | 相似度是**不可归因**的变量，会污染漂移归因。代价是同义改写可能召不回 |
| **不做无人值守运行** | 没有调度器与常驻进程 —— 只能等用户开口时随回复附上 |
| **不假装有情绪** | 情绪是数值记账，代码里明确声明它 ≠ 主观感受 |
| **不做真实推送** | 主动消息无法送达，只能在下一轮附上 |
