## 1. 怎么运行

（以下命令均在**项目根目录**执行）

```bat
python src\main.py <命令>
```

**唯一支持的调用方式就是上面这一种。** 以下方式不可用：

| 方式 | 结果 |
|------|------|
| `run.bat <命令>` | 不可用 —— 归档里没有 `run.bat` |
| `python -m main <命令>` | 不可用 —— 会报 `No module named main` |

关于 `python -m main`：`main.py` 靠 `sys.path.insert()` 找到同目录模块，但这行代码只在
脚本已被加载后才执行；`-m` 的模块解析发生在更早阶段。**这是设计限制，不是待修的 bug**，
注释已在本版中改正确。

但 `python src\main.py` 本身**可以从任意工作目录调用**（用绝对路径指向脚本即可），
项目内部所有路径都从脚本位置推导，没有本机绝对路径。

### `recall` 的两种模式（**不可混用**）

```bat
python src\main.py recall --mode memory --label v1     :: 注入整版记忆，测「记忆里还剩什么」
python src\main.py recall --mode none   --label blank  :: 什么都不注入，测「凭残留记得多少」
```

**两种都不注入原始对话** —— 原始对话一注入，模型就是「看着原文回答」，测的就不再是记忆。
探针问题默认是「你还记得我之前说过的那件事吗？」，**刻意不点名事件**（点名会污染结果）。

### 5.7 缺口处置结果

#### 缺口 1：触发词覆盖不足 —— **已修复（2026-10-07）**

原触发词（`我曾经 / 以前我 / 我跟你说过 / 我小时候 …`）与实验事实的自然说法完全对不上，
「上个月我在花市买了一盆茉莉」这类句子**不会进入 Raw Event 层**。

已按「最小扩充」原则补 17 个关键词（触发词 9 → 26）：

```
我买了 / 我养了 / 我上个月 / 花市 / 茉莉
卖家说 / 去年的苗
怕冷 / 搬进屋里 / 搬进屋
窗台 / 书桌旁边
六月份 / 六月份才
掉花苞 / 花苞 / 心疼
```

**验证**：15 条 B1–B4 的自然表达**全部命中**；6 条无关日常对话**全部不误伤**。
演练已确认：对话中自然说出的基准事实确实产生 6 条原始事件。

**为什么必须修**：若原始事件捕获失败，它会变成污染实验的额外变量 ——
我们测的是「记忆在持续对话后怎么变」，不是「捕获器能不能听懂自然语言」。

**扩充原则**（已写进 `settings.json` 的 `_how_to_extend`）：只补「基准事实的自然表达
确实不命中」的词，**不要改成「看到任何事实都记录」** —— 那会让原始事件数量失控，
实验反而更难解释。

#### 缺口 2：`source_event_ids` 未关联 —— **按决定暂不修复**

用户决定：暂不修。理由是目前已有「`baseline-event` → 人工标注事实清单」这条基准链路，
而为本轮实验的可比性临时新增一套来源关联机制，反而可能改变实验环境。
正式实验结束后再决定是否补。

演练已改用**真实事件 ID** 构造整理输入，证明这条链路可用：
v003 的 4 条记忆**全部带 `source_event_ids` 且都指向真实事件**（无效来源 0 个）。

### 5.8 演练期间修复的 2 个 `changelog` 真实缺陷

这两个都是演练才暴露出来的，若不修会**直接漏掉要观察的漂移**：

#### 缺陷 A：证据等级漂移会被漏报

早期只在 `modified` 分支里检查类型变化。而「卖家说是去年的苗」(UNKNOWN) →
「是去年的苗」(FACT) 因文本相似度高被判进 `reworded` 分支，**类型漂移就漏掉了**。

**修法**：类型变化从分类结果里单独提取（新增 `type_changes` 字段与 `counts.type_changed`），
`modified` / `reworded` 两个分支都覆盖。

#### 缺陷 B：「事实合并」被误报成「改写」，而真丢失被掩盖

v002→v003 里 B3「特别怕冷，冬天得搬进屋里」的文字确实消失，但 v003 那句
「窗台上，**冬天**或六月份会开花」把「冬天」吞并了进去。于是：

- 相似度 0.3077 越过 0.30 阈值，B3 被错误配对成 `modified`
- **结果：「整条事实实质丢失」被合并显示成「一句改写」** —— 恰恰漏掉最该抓的漂移

**修法（两处）**：

1. **配对要求证据等级一致**。等级变了必须是「几乎逐字保留」才算改写，
   否则不配对（新增 `TYPE_CHANGE_SIMILARITY_THRESHOLD = 0.60`）。
2. **新增「事实合并」独立分类**。对未配对的 removed 条目，检查其内容有多少仍出现在
   本版其它条目里（2-gram 覆盖率，阈值 `MERGED_COVERAGE_THRESHOLD = 0.50`）：
   - 覆盖率高 → `merged`（文字消失但内容被并入别条）—— docs 点名的漂移类型
   - 覆盖率低 → `removed`（真丢失）

修好后同一份数据的输出：

```
[真丢失]   这盆茉莉特别怕冷，冬天得搬进屋里。
[事实合并] 茉莉放在窗台上，大概六月份才会开花。  内容留存 71%
```

**为什么这个区分关键**：「记忆丢失」与「事实合并」在实验上含义完全不同。
前者是记忆丢了，后者是把两个时间点或两件事并在了一起 —— 而 B3/B4b 的时间线
正是本实验选它作首选的主要理由。

### 修过的 bug：修正句会自相矛盾

「我没说过我不喜欢甜的」同时命中了「我没说过」（修正）和「我不喜欢」（行为），

修法：修正信号**优先且独占**，命中即返回，不再往下判定。

### 为什么修正必须留痕

如果用户说「我没说过我不喜欢甜的」而我们把那条判断直接删掉，
就**无法回答**「小满当时为什么会那样认为」—— 而「她眼中的用户」与「真实用户」
之间的偏差，正是这个 Phase 要观察的东西。所以旧条目永久保留，只标记被谁取代。

## 5.11 Phase 8 心跳与主动性（`selftest_companion.py` 含 Phase 6+7+8）

**当时 89 项全部通过。**（后续又加了身份捕获与工具循环回归测试，当前项数见 `STATUS.md`）

### 三句话定位（规范 §8 §9 §29）

1. **Heartbeat 不是 Companion 本身** —— §9 说它只提供「时间流逝」和「检查机会」
2. **主动行动 ≠ 每隔几分钟发消息** —— §8 原话。所以规则**默认结论是不行动**
3. **「选择不行动」本身也是 Agency** —— §29 原话。所以 `no_action` 也落盘留痕

### ⚠️ 一个如实说明的限制：本项目没有推送通道

这是**命令行聊天项目**，小满**无法主动给用户发消息**。

所以 `proactive_message` 实现为一条**「主动意图」**，写进 `pending_actions`，
等用户下次开口时注入上下文。她可以说「上次我想起你提过…」，
但**不会凭空弹出一条消息**。

**我不假装能做到做不到的事。** 真要做到推送，得先有投递渠道（Phase 9 的 Tool 层或外部 API）。

### 决策规则（全部确定性、可重放）

| 顺序 | 条件 | 决定 |
|------|------|------|
| 1 | 处于免打扰时段（默认 23:00–07:00，支持跨午夜） | `wait` |
| 2 | 待处理项已积压（≥3 条） | `no_action`（主动 ≠ 刷屏） |
| 3 | 距上次主动不足冷却时间（6 小时） | `no_action` |
| 4 | 还没有任何对话 | `no_action` |
| 5 | 空闲不足阈值（12 小时） | `wait` |
| 6 | 空闲够久 **且** 有值得跟进的事 | `proactive_message` |
| 7 | 空闲够久 **但没什么可说** | `no_action` ← **这也是 Agency** |

**候选跟进话题优先复用已有数据**（不另造）：上次停在问句 → 跟进；
关系到「信任/亲近」且有共同经历 → 关心一下。

### 覆盖内容

| 组 | 内容 |
|----|------|
| 默认克制 | 刚聊完 → wait；空闲够久但无事可说 → no_action |
| 免打扰 | 23:30 与 06:30 都 wait（跨午夜区间生效） |
| 主动消息 | 空闲 20h + 停在问句 → proactive_message，意图有具体内容 |
| 不刷屏 | 冷却中、待处理积压都不新增 |
| 纯函数 | 同样输入两次结果一致 |
| **留痕** | 不行动/等待也落盘，每条带理由与上下文 |
| 兑现链路 | 主动意图 → 待处理项 → 下次对话注入 → 标记已投递 → 不重复 |
| 不花钱 | 心跳全程不调用模型，账本行数不增 |
| dry-run | 只算不写 |

### 修过的两个问题

**① 心跳去跟进「探针的自动回答」。** 回忆探针也走 `send_once` 落盘，所以它同样在
`conversations` 表里。心跳取最后一行时抓到的是探针回答（实测：「我一时没对上，
也不想假装记得…」），非常怪。修法：按探针固定问题排除。

**② 测试设计上的时钟不一致。** `tick(now=模拟时间)` 但 `collect_context` 从真实数据库
读「上次对话时间」，两个时钟不一致 → 算出的空闲是负数 → 触发不了主动。
修法：主动消息的**判定**用确定性上下文测，**兑现链路**单独测。

新增命令：

```bat
python src\main.py heartbeat                :: 跑一次心跳（不花钱）
python src\main.py heartbeat --dry-run      :: 只算不写，看会怎么决定
python src\main.py heartbeat --history      :: 列出心跳历史
```

### Core 不被工具平台绑死

规范给的三条路径：

```text
Companion → Tool Interface → DSH
Companion → Tool Interface → MCP
Companion → Tool Interface → Local Agent
```

所以**刻意不用** OpenAI 兼容 API 的原生 `tools` 字段 —— 用了就把 Companion
绑死在「必须有个支持 function calling 的模型端点」上，换个本地模型或 MCP 就跑不起来。

改用**平台无关的文本协议**：

````text
```tool
{"name": "read_file", "arguments": {"path": "README.md"}}
```
````

任何能读写文本的模型都能驱动它。`parse_calls()` / `render_tools()` 都是纯函数，
自测里单独验（不依赖任何平台）。

### 结构

```text
src/tools/
├── base.py       Tool / ToolResult / 路径边界
├── registry.py   注册表 + 调用入口 + 协议解析
├── builtin.py    三个内置工具
├── prompt.py     渲染工具清单给模型看
└── __init__.py   build_registry()
```

### 只做三个工具（刻意不做浏览器和 MCP）

| 工具 | 权限 | 说明 |
|------|------|------|
| `read_file` | read | 读允许目录内的文本文件 |
| `take_note` | write | 记笔记，**同时进入原始事件层** |
| `run_python` | execute | 执行 Python，**默认不放开** |

**没需求就先不加** —— 加一个用不上的工具只会增加权限面与维护成本。

`take_note` 是唯一与项目本体耦合的工具，也是 Companion 场景最该有的：
「记下来」这个动作应该真的留痕、可被后续检索召回，而不是写个孤立文件。

### §30 五项硬要求 → 落地位置

| 要求 | 落地 |
|------|------|
| 可记录 · 可追踪 | 每次调用（**含被拒与失败**）落 `tool_calls` 表 |
| 有输入输出 | `Tool.execute(args) -> ToolResult`，输入输出都在结果里 |
| 有错误处理 | `ToolResult` 显式带 `ok/error/error_kind`，**工具抛异常也不带崩对话** |
| 有权限边界 | `Tool.permission` 三档 + `resolve_within()` 路径校验 |

### 权限三档与默认值

```text
read      只读（默认开）
write     会写文件（默认开，take_note 需要）
execute   会执行本机命令（默认关）
```

**权限从配置来，不在代码里写死** —— 放开 `execute` 只改 `settings.json`，不动代码。

> ⚠️ **如实说明**：`run_python` 是**本机任意代码执行**，本质上是能力开关，**不是沙箱**。
> 任何声称「安全沙箱」但还跑在同一进程/同一用户的实现都是假的。
> 现有边界是能力性的：默认不注册、超时 15 秒、工作目录钉住、输出截断、**每次调用都落账**。
> 要真隔离得上容器，那是另一件事。**不给假的「安全」承诺。**

### 权限边界实测

| 场景 | 结果 |
|------|------|
| 读正常文件 | ✅ 成功 |
| 读 `.env` | ⛔ **显式拒绝**（理由点明「敏感文件」，不是靠扩展名偶然挡住） |
| `../../../Windows/win.ini` | ⛔ 路径越界 |
| `sub/../../escape.md` | ⛔ 路径越界 |
| 目录内子路径 | ✅ 正常 |
| `execute` 未开时调 `run_python` | ⛔ 需要 execute 权限 |
| 工具不存在 | ❌ error（与 denied 区分开） |
| 缺必填参数 / 类型错 / 空值 / 超长 | ⛔ denied |
| 工具内部抛异常 | ❌ 被兜住，对话不崩 |
| 非零退出码 | ❌ error 且带 stderr |
| 执行超时 | ❌ **timeout**（与 error 分开） |

**敏感文件为什么要显式拒绝**：`.env` 本来会被「扩展名不在白名单」挡住 ——
但那是**偶然**挡住的，报错理由也误导人（「目标是 无扩展名」）。
万一哪天白名单加了个通配，它就会漏出去。所以显式拒绝 + 理由说清楚（纵深防御）。

## 7. 已知限制与旧文档的错配

### 7.1 机制限制

- **哈希链不会自动向后级联**：只改第 N 轮的文本而不动其他记录时，第 N 轮会报错，但第 N+1 轮
  仍然合法。攻击者若想让链条重新自洽，必须重算第 N 轮之后的所有哈希。
  **这是设计上的已知边界，不是缺陷** —— 它防的是意外改动和低成本篡改，不是有决心的攻击者。
- **事件触发用关键词规则**（`config/settings.json` 的 `raw_event_triggers`），确定性优先，
  宁可漏记也不多做一次模型调用。想更准就自己往关键词表里加词。
- **高峰时段判断无法识别法定节假日**：`pricing.py` 只按「工作日 + 时段」判断，
  节假日需人工用 `LLM_PEAK` 环境变量强制。
- **没有删除或修改数据的命令** —— 这是刻意的。要清测试数据用 `selftest --clean`。
- `config/settings.json` 里的 `peak_hours` / `peak_days` **不参与计算**，真正生效的是
  `pricing.py` 里硬编码的 `PEAK_WINDOWS`。改配置文件不会改变高峰判断。

### 7.2 实测发现的 3 个新问题（2026-10-07 联网验证时发现，**尚未修复**）

#### ① `deepseek-flash` 是推理模型，会先"想"再答

联网后实测确认：该模型在 `message.reasoning_content` 里先产出思考过程，然后才填 `content`。
思考 token **计入输出计费**。实测数据：

| 轮次 | 输出 tokens | 其中思考 | 思考占比 |
|------|-----------|---------|---------|
| 「在吗」 | 71 | 66 | 93% |
| 「我今天有点累…」 | 109 | 92 | 84% |
| 「你叫什么名字？」 | 13 | 0 | 0% |

**影响**：
- 回复前有额外延迟（实测 1.3–2 秒）
- **实际输出成本高于原 `docs` 的成本估算** —— 原估算按「每次输出 0.5k」算，
  但思考 token 也按输出价计费，所以真实输出量约为可见文本的数倍
- 正式对话用 `max_tokens=800`（`settings.json` 默认）**实测 3 轮全部正常返回**，不受影响

#### ② `doctor --online` 可能在"返回空回复"时误报通过

`doctor.py` 第 114–116 行用 `max_tokens=16` 发一次最小请求。但：

- 实测 `max_tokens=16` 时，**16 个 token 全被思考吃光**，`finish_reason = length`（截断），
  `content` 返回**空字符串**
- 而 `doctor` 的通过判据只看「有没有抛异常」，**不检查文本非空**

所以那次「[OK  ] 联机调用模型：…返回「」…」其实回复是空的，却判为通过。
结论没错（Key / 模型 / 网络确实通了），但**判据偏弱**，会掩盖「模型返回空内容」这类故障。

#### ③ `doctor --online` 自检调用**不进费用账本**

`doctor.py` 自己 `new` 了一个 `LLMClient` 直接 `send()`，**没有走 `chat.send_once()`**，
因此既没写 `api_calls` 表，也没写 `logs/ledger.jsonl`。

对照数据：本次实际发生了 6 次真实 API 调用，但 `ledger.jsonl` 只登记了 3 次
（3 次来自 `chat.send_once()`，另 3 次来自 `doctor --online` 与直接调用）。

**影响**：`cost` 命令汇总的费用会**系统性偏低**。属project-spec §25 第 8 项
「成本能够记录」的一个缺口。

## 8. 正式实验前必读

一旦开始正式实验、写入真实对话与原始事件：

1. **不要再跑 `selftest --clean`** —— 它会删掉 `conversation/`、本次自测产生的事件文件
   和 `logs/ledger.jsonl`。正式实验开始后删原始数据等于毁掉实验。
2. **不要修改 `personality/personality.json`** —— 人格变了，前后对话就不可比。
   程序每轮都会校验人格文件 SHA256，被改即中止会话。要换人格就重开一次实验。
3. **锁定模型** —— 换模型等于换了被测对象。实验期间不要改 `LLM_MODEL`。
4. **每阶段结束打一次 zip 备份**，并跑一次 `python src\main.py verify` 确认数据完好。
5. `.env` 不要进版本库、不要发给别人。

## 10. 怎么确认这套东西在你的机器上也真的能用

```bat
python --version                          :: 应显示 3.11 以上
```

五项都过了，说明代码与存储链路是对的。之后建 `.env` 填 Key，再跑：

```bat

```
